## 🌟 نظرة عامة على النظام

تم تصميم هذا النظام ليلبي المتطلبات المحاسبية والضريبية للمنشآت في المملكة العربية السعودية:
- **دليل حسابات شجري خماسي المستويات** متوافق مع المعايير المحاسبية المعتمدة.
- **قيود يومية مزدوجة** بآليات تدقيق التوازن الفوري (Halala Integer Precision).
- **إدارة الفترات المالية** وضوابط الإقفال السنوي والشهري ومنع الترحيل في الفترات المغلقة.
- **نظام نقاط البيع (POS)** يدعم الفروع والصناديق، تعليق الطلبات، وورديات الكاشير مع المطابقة النقدية.
- **حماية شاملة للاعتماديات** تمنع حذف الحسابات أو الأصناف أو الفروع المرتبطة بحركات مالية نشطة.
- **استيراد وتصدير النسخ الاحتياطية** مع فحص صارم للمخطط (Zod Schema Validation) وتجريد فوري للمفاتيح الحساسة.

## 🚀 طريقة التشغيل داخل Google AI Studio

عند استخدام التطبيق داخل منصة **Google AI Studio**:
1. يعمل التطبيق تلقائياً عبر حاوية سحابية مهيأة بدون الحاجة لأي تثبيت يدوي.
2. يتم تشغيل الخادم على المنفذ `3000` (المنفذ المعتمد والوحيد للاتصال عبر الوكيل العكسي).
3. مفتاح الذكاء الاصطناعي `GEMINI_API_KEY` ورابط الاستضافة `APP_URL` يتم حقنهما تلقائياً عبر إعدادات البيئة في المنصة.
4. تظهر واجهة المعاينة الحية فوراً مع تفعيل وضع العرض التجريبي (`VITE_DEMO_MODE=true`).

## 💻 طريقة التشغيل محلياً (Local Development)

### المتطلبات الأساسية:
- **Node.js**: الإصدار `18.x` أو `20.x` أو أحدث.
- **npm**: الإصدار `9.x` أو أحدث (أو `pnpm` / `yarn`).

### خطوات التثبيت والتشغيل:

1. **استنساخ المستودع (Clone Repository):**
   ```bash
   git clone <REPO_URL>
   cd saudi-accounting-system
   ```

2. **تثبيت الحزم البرمجية (Dependencies):**
   ```bash
   npm install
   ```

3. **إعداد ملف المتغيرات البيئية:**
   قم بنسخ ملف `.env.example` إلى `.env`:
   ```bash
   cp .env.example .env
   ```
   *(اختياري)*: أضف مفتاح `GEMINI_API_KEY` في ملف `.env` إذا رغبت في استخدام ميزات التحليل الذكي للقيود محلياً.

4. **بدء خادم التطوير (Start Dev Server):**
   ```bash
   npm run dev
   ```
   سيتم تشغيل الخادم على الرابط: `http://localhost:3000`

## 🏭 طريقة بناء وتشغيل الإنتاج (Production Build & Run)

يستخدم النظام بنية خادم متكاملة (Express Backend + Vite Frontend Bundle):

1. **بناء نسخة الإنتاج (Production Build):**
   ```bash
   npm run build
   ```
   يقوم هذا الأمر بتجميع:
   - واجهة المستخدم الثابتة المحسنة في مجلد `dist/`.
   - خادم Express في ملف تنفيذي موحد `dist/server.cjs` عبر `esbuild`.

2. **تشغيل خادم الإنتاج (Start Production Server):**
   ```bash
   npm start
   ```
   يعمل الخادم المجمّع فوراً ويخدم كل من واجهات الـ API وملفات الواجهة الثابتة بكفاءة وسرعة فائقة.

## ⚙️ المتغيرات البيئية (Environment Variables)

| المتغير | الوصف | القيمة الافتراضية | إلزامي؟ |
| :--- | :--- | :--- | :--- |
| `PORT` | المنفذ الذي يستمع له خادم التطبيق | `3000` | نعم |
| `NODE_ENV` | بيئة التشغيل (`development` أو `production`) | `development` | نعم |
| `VITE_DEMO_MODE` | وضع العرض التجريبي وتفعيل المحرك المحلي للبيانات | `true` | اختياري |
| `GEMINI_API_KEY` | مفتاح Gemini API للمستشار المالي وتدقيق الذكاء الاصطناعي | `""` | للخدمات الذكية فقط |
| `APP_URL` | الرابط الأساسي للمنصة والمصادقة والخدمات الخارجية | `http://localhost:3000` | اختياري |
| `JSON_BODY_LIMIT` | الحد الأقصى لحجم حمولة طلبات JSON | `1mb` | اختياري |

> ⚠️ **ملاحظة أمنية هامة**: مفتاح `GEMINI_API_KEY` يتم التعامل معه **في جانب الخادم فقط (Server-Side)** ولا يتم تسريبه أو تعريضه للمتصفح إطلاقاً.

## 💾 طبيعة التخزين الحالي (In-Browser Storage)

- **آلية الحفظ الحالية**: يعتمد النظام في هذا الإصدار على **محرك التخزين المحلي للمتصفح (Browser LocalStorage & Indexed Storage Layer)** مع بنية نمط المستودع (`LocalStorageAccountingRepository`).
- **البيانات التجريبية الافتراضية**: يتم تحميل بيانات تجريبية محاسبية واقعية عند بدء النظام لأول مرة أو عند الضغط على "إعادة ضبط البيانات الافتراضية".
- **النسخ الاحتياطي**: يتوفر خيار تصدير واستيراد كامل لقاعدة البيانات بصيغة JSON مع تحقق فوري وصارم قبل التثبيت.
- **تنبيه**: مسح ذاكرة المتصفح المؤقتة (Clear Browser Storage) يؤدي إلى مسح البيانات المحلية غير المصدّرة.

## 🏛️ تكامل هيئة الزكاة والضريبة والجمارك (ZATCA Phase 2 Simulation)

يتضمن النظام **محرك محاكاة وتدقيق محلي متقدم** للمرحلة الثانية من الفوترة الإلكترونية:

### ما يوفره النظام حالياً:
1. **تشفير TLV Base64**: ترميز الحقول التسعة الإلزامية للفاتورة الضريبية والمبسطة (اسم المورد، الرقم الضريبي، الطابع الزمني، الإجمالي، الضريبة، الهاش، التوقيع الرقمي، المفتاح العام، توقيع الشهادة).
2. **حساب التجزئة (SHA-256 Hash)**: استخراج الهاش المعتمد للفاتورة بصيغتي Base64 و Hex.
3. **توليد مستندات UBL 2.1 XML**: إنشاء البنية الشجرية الكاملة لملف XML المطابق لمواصفات الهيئة.
4. **فحص قواعد العمل المحلية (BR-KSA-01 إلى BR-KSA-08)**:
   - التحقق من الرقم الضريبي المكون من 15 رقماً ويبدأ وينتهي بالرقم 3.
   - التحقق من العنوان الوطني وتفاصيل المورد والمشتري.
   - التحقق من الرموز المميزة UUID ومطابقة الأرقام المتسلسلة والمجاميع الحسابية.

### ⚠️ تنبيه قانوني وفني هام:
> محرك الزكاة في هذا الإصدار مخصص **للفحص الهندسي والمحاكاة والتحقق المحلي (Local Validation & Compliance Simulation)**، **ولا يقوم بالإرسال الحي أو الربط الشبكي المباشر (Clearance & Reporting)** مع واجهات API الرسمية لهيئة الزكاة والضريبة والجمارك (Fatoora Portal).

## 🚧 القيود الحالية وخارطة الطريق قبل الاستخدام الإنتاجي

قبل اعتماد النظام للاستخدام الإنتاجي الحي في منشأة حقيقية، يجب استكمال المتطلبات التالية:

1. **قاعدة البيانات المركزية (PostgreSQL / Cloud Database)**:
   - *الوضع الحالي*: تخزين محلي بالمتصفح.
   - *المطلوب للإنتاج*: ربط قاعدة بيانات سحابية موثوقة (مثل PostgreSQL عبر Drizzle/Prisma أو Firebase Firestore) لتخزين مركزي متزامن بين الفروع.

2. **المصادقة وإدارة الصلاحيات (Authentication & RBAC)**:
   - *الوضع الحالي*: مستخدم تجريبي افتراضي بدون تسجيل دخول.
   - *المطلوب للإنتاج*: نظام تسجيل دخول حقيقي وجلسات آمنة (JWT / OAuth / Firebase Auth) مع أدوار وصلاحيات محددة (مدير، محاسب، كاشير).

3. **شهادات CSID والربط الحي مع ZATCA**:
   - *الوضع الحالي*: محاكاة محلية للأختام والشهادات.
   - *المطلوب للإنتاج*: إنشاء مفاتيح ECDSA (secp256k1) حقيقية، استخراج طلب توقيع الشهادة (CSR)، والحصول على شهادة الامتثال والإنتاج (CSID) عبر بوابة زاتكا وتوقيع مستندات XML رقمياً وإرسالها عبر بروتوكولات REST/SOAP.

## 🔒 الأمان وحماية المفاتيح السرية (Security & Secrets)

تم اتخاذ تدابير أمنية صارمة في هذا المستودع:
- **ملفات `.env` محجوبة بالكامل**: تم إدراج ملفات `.env*` في `.gitignore` لمنع رفع أي بيانات اعتماد سرية إلى مستودعات Git.
- **تجريد النسخ الاحتياطية**: محرك التصدير `exportDataJson` يقوم تلقائياً باستبعاد وتجريد أي مفاتيح تشفير أو أسرار API قبل تنزيل ملف JSON.
- **حماية ترويسات HTTP**: الخادم مزود بمكتبة `Helmet` وحماية معدل الطلبات `express-rate-limit`.
